# The Commodore 128

Sources:
- C64-Wiki, "Commodore 128/Memory Model", https://www.c64-wiki.com/wiki/Commodore_128/Memory_Model
- zimmers.net, the C128 RAM map, https://mirrors.archeobits.com/commodore/www.zimmers.net/anonftp/pub/cbm/maps/C128ram.txt

From the sources (not yet checked on the machine):
- 128 KiB of RAM in two 64 KiB banks (RAM 0 and RAM 1); the MMU (MOS 8722) maps them for the 8502 CPU.
- Common RAM: an area always backed by bank 0, set by the MMU's configuration register, from 1 KiB up to 16 KiB;
  at power-up 1 KiB at the bottom.  With common RAM at the bottom, the zero page and the stack go to bank 0 whatever
  the page registers say.
- The VIC-IIe reads either bank: bits 6-7 of the MMU's **RAM** configuration register ($D506) choose the video
  bank (0 = bank 0, 1 = bank 1; confirmed by "Mapping the Commodore 128", below); the 16 KiB VIC bank inside it from
  CIA 2, as on the C64.
- Colour RAM: two nibble banks independent of RAM 0/1; bit 0 of $01 chooses the CPU's, bit 1 the VIC's.
- VICE: x128 (checked: installed).

## The MMU, from "Mapping the Commodore 128" (Ottis R. Cowper, COMPUTE! Books, 1986), pages 408-425

- **$FF00 / $D500, the configuration register** (one register, two addresses): "accessible [at $D500] only when the
  I/O block is visible, whereas it is always accessible at 65280/$FF00, regardless of the memory configuration".
  Bit 0: $D000-$DFFF, 0 = the I/O block (chips and colour RAM), 1 = what bits 4-5 say.  Bit 1: $4000-$7FFF, 0 = BASIC
  ROM (low part), 1 = RAM of the block in bits 6-7.  Bits 2-3: $8000-$BFFF, 00 BASIC ROM high + monitor, 01 internal
  function ROM, 10 external function ROM, 11 RAM.  Bits 4-5: $C000-$FFFF, 00 screen editor ROM ($C000-$CFFF),
  character ROM ($D000-$DFFF), KERNAL ROM ($E000-$FFFF); 01/10 function ROMs; 11 RAM.  Bits 6-7: the RAM block (only
  bit 6 significant in the MMU of the 128 KiB machine).  So all RAM of block 0 with the I/O visible = **$3E** (and
  block 1 = $7E: the book's own example writes $7E "Make I/O block visible" while in block 1).
- **$FF00-$FF04 always overlay the RAM**: "The MMU configuration and load configuration registers always appear at
  65280-65284/$FF00-$FF04, regardless of the settings of these bits."  A program cannot keep data there.
- **$FF01-$FF04, load configuration registers**: storing any value loads the configuration register from the matching
  preconfiguration register $D501-$D504 (BASIC sets $D501 $3F bank 0, $D502 $7F bank 1, $D503 $01 bank 14, $D504 $41).
- **$D506, the RAM configuration register**: bits 0-1 the common areas' size (00 1K, 01 4K, 10 8K, 11 16K), bits 2-3
  where (00 none, bottom, top, both: Figure 8-15); "the RAM seen as common is always that from block 0"; a top
  common area is visible only when bits 4-5 of $FF00 select RAM there.  Default after RESET: %0100 = 1K at the bottom
  ($0000-$03FF).  Bits 6-7: the block the VIC's video bank is seen in, "without regard for the common area
  specification" (the VIC sees memory hidden from the processor).  "The operating system will crash if an interrupt
  occurs while the system is configured for block 1 RAM with the common area disabled."
- **$D505, mode configuration**: bit 0 Z80 (0) / 8502 (1); bit 6 C64 mode; bits 4-5 GAME/EXROM (read); bit 7 the
  40/80 key (read).
- **$D507-$D50A**: page 0 and page 1 relocation (page and block pointers).  **$D50B**: the MMU's version.

## The KERNAL and the system, from "Mapping the Commodore 128" (each checked in x128 as noted)

- **Boot sector** (BOOT_CALL $F890, jump table $FF53): track 1 sector 0 read into $0B00-$0BFF; bytes 0-2 "CBM";
  3-4 the address for more boot sectors, 5 their bank, 6 their count; then a message printed after BOOTING, ended by
  0; then a file name ended by 0 (the file, PRG, is loaded into bank 0 with LOAD); then machine code, called with
  JSRFAR in bank 15.  **Checked**: src/c64/disco128/abadia128ks.d64 boots in x128.
- **$1300-$1BFF** is free for programs; cc65's c128 programs use $1C00-$BFFF (its doc) and run with the KERNAL ROM
  and the I/O ($FF00 = $0E).
- **SETBNK $FF68**: A = the bank of the data to load or save, X = the bank of the file name.  **FA $BA** the device;
  by the time cc65's program runs it is 3 (the screen), so the boot drive is kept apart.
- **LOAD $F265**: after each byte the pointer is incremented and compared with $FF00: reaching it gives error 16,
  out of memory, even after the last byte.  **Checked** (a file ending at $FEFF failed with A = $10).
- **NDX $D0** keyboard buffer count, **KEYBUF $034A-$0353**; **VM1 $0A2C** the 40-column screen's $D018 shadow ($14
  upper case at $1000, bit 1 toggles to $1800: $16 lower case); **LOCKS $F7** bit 7 = SHIFT + C= cannot switch the
  set (CHR$(11) / CHR$(12)); **$D8** the screen mode flag: $FF makes the screen editor's interrupt leave the VIC-II
  alone; **$FB-$FE** free zero page.
- **The system interrupt is the VIC-II's raster at line 255** (SCNIRQ $C194), not CIA 1's timer A as on the C64.
  Every IRQ enters through JIRQ $FF17 (A, X, Y and the MMU's configuration pushed, bank 15 set, JMP ($0314)) and
  leaves through $FF33 (all restored).  Bank 15 shows the RAM only below $4000.  **Checked** in x128 (the
  presentation's music interrupt).
- **CLKRATE $D030** bit 0: 2 MHz.  The VIC-II cannot show a picture then (bit 4 of $D011 is usually cleared); the
  other I/O chips are reached through clock stretching (an effective 1 MHz access).  The KERNAL's serial routines
  go to 1 MHz by themselves.  **Checked**: 2 MHz in the border only (CIA 2's NMIs) shows a clean picture and gives
  the game 20 % (300 frames: 19.6 -> 15.7 s emulated).
- **Error numbers** (I/O error handler $F67C): 1 too many files, 2 file open, 3 not open, 4 not found, 5 device not
  present, 6 not input, 7 not output, 8 missing name, 9 illegal device, 16 out of memory.
- Writing a ROM address writes the RAM under it (cc65's c128 crt0.s: "Writing through the ROM to the underlying RAM
  works").  **Checked** (the presentation's picture copied to $E000 with the KERNAL in).
