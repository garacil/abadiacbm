## The 6509 and the banks

- MOS 6509, the 6502's instruction set and no other instruction; two registers present at $0000 and $0001 of every
  bank: the execution bank (where instructions and every plain access go) and the indirect bank, which only
  `LDA (zp),Y` and `STA (zp),Y` use.  Every other `(zp),Y` instruction (CMP, ADC, AND...) reads the execution bank
  (checked: a `CMP (zp),Y` against an I/O register reads bank 0's RAM instead).  Writing $0000 switches the bank of
  the next instruction fetch at once: the cross-bank calls rely on `STA $00` followed by the next instruction at the
  same address in the other bank.  Both registers read back (cc65's crt0.s reads them).
- Up to 16 banks of 64 KiB (1 MiB); the P500 has 128 KiB, banks 0 and 1.  Bank 15 is the system bank: its own RAM
  below $0800 (the KERNAL's zero page, stack and variables), BASIC at $8000, the I/O at $D000-$DFFF, the KERNAL at
  $E000.
- Interrupts are taken in the bank that runs, through that bank's $FFFA-$FFFF.

## The I/O (bank 15)

| Address | Chip | |
|---|---|---|
| $D000 | the text screen RAM (the KERNAL's) | |
| $D400 | the colour RAM | 1 KiB |
| $D800 | VIC-II | its registers in the C64's order |
| $DA00 | SID | |
| $DC00 | 6526 CIA | timers; port B bits 0-3 game port 1's directions, 4-7 port 2's; port A bit 6 port 1's trigger, bit 7 port 2's (the 700 Reference Guide; cc65's joystick driver) |
| $DE00 | 6525 TPI 1 | the interrupt controller: register 5 the mask, register 7 the active interrupt (bit 0 the 50 Hz ticker, bit 1 IEEE SRQ, bit 2 the 6526, bit 3 the external port, bit 4 the ACIA); register 6 the control, its bits 4-7 the CA and CB lines: %1010 puts the VIC-II's screen RAM and bitmap in bank 0 (cc65's crt0.s; the game's plataforma/interrupcion500.s) |
| $DF00 | 6525 TPI 2 | the keyboard: port A ($DF00) columns 8-15, port B ($DF01) columns 0-7, port C ($DF02) bits 0-5 the rows (0 = down); port C bits 6-7 the VIC-II's 16 KiB (11: $C000-$FFFF) |

- The VIC-II sees bank 0 when TPI 1's CA and CB are both low (control bits 4-7 = %1010); with the value the 2016
  parchment code writes ($03) it shows nothing of a bitmap at $E000 (checked).
- The 6526's interrupt reaches the CPU through TPI 1's input 2.  The acknowledgement order that works (checked in
  VICE): read the 6526's flags, write TPI 1's active interrupt register back, read the 6526's flags again.  Writing
  TPI 1 first, with the 6526's line still down, makes the interrupt come again at once, for ever; reading the 6526 only
  before TPI 1 loses an interrupt that falls between the two (the 6526's line then stays down and no other edge
  comes).

## The keyboard (ROM $E933-$E9EA, the key tables from $EAB1)

16 columns x 6 rows: a column selected by a 0 on its line (port B bit c for columns 0-7, port A bit c-8 for 8-15),
the rows read on port C bits 0-5 until two reads agree; key index 6 x column + row, the order of the table at $EAB1
(normal), $EB11 (shifted), $EB71, $EBD1.  Column 0: F1, ESC, TAB, C=, SHIFT, CTRL; columns 1-9: F2-F10 on row 0 and the
letters and digits; column 10: CRSR down, =, _, ], RETURN, pi; column 11: CRSR up, CRSR left, CRSR right, DEL; columns
12-14 the numeric keypad and CLR/HOME, RVS, NORM; column 15: STOP, /, -, +, ENTER.  SHIFT + RUN/STOP types
`dL"*` RETURN `RUN` RETURN (the bytes at $EC31): the first program of the disk is loaded and run.

## The KERNAL

- The jump table at $FF6F-$FFF5 (SETLFS $FFBA, SETNAM $FFBD, OPEN $FFC0, CLOSE $FFC3, LOAD $FFD5, SAVE $FFD8...).
  SETNAM ($FB40) copies a 3-byte pointer (address, bank) from the zero page at X to FNAM $90-$92 and the length A to
  $9D; SETLFS ($FB4F) writes LA $9E, FA $9F (the device), SA $A0; SAVE ($F853) copies its start (X) and end (Y)
  pointers, 3 bytes each, to $99-$9B and $96-$98: the variables can be written directly in bank 15's zero page.
  LOAD: A bit 7 = verify, A bits 0-3 = the bank to load into, X/Y the address ($FF/$FF: the file's own).  OPEN with
  C = 0 is a plain open (cc65's kopen.s).
- The cross-bank call (ROM $FEC3-$FF2C; cc65's crt0.s callbank15 does the same): bank 15's stack, its pointer kept
  at $F:$01FF, gets the bank to come back to, $FEFD (the way back), the registers, the routine's address - 1 and $FF25;
  the caller's stack pointer is kept at its own bank's $01FF; `STA $00` at $FFF6 (STA $00 / RTS in both banks) moves
  the CPU to bank 15, whose RTS enters $FF26 (PLA TAY PLA TAX PLA PLP RTS) and the routine.  Its RTS goes to $FEFE,
  which puts the results on the caller's stack, below the pointer kept at the caller's $01FF, and comes back through
  $FFF6 and the caller's $FF26.  So the calling bank needs $FF26-$FF2C and $FFF6-$FFF8 as bank 15 has them, and its
  $01FF free (or kept aside).
- The keyboard buffer: $03AB, ten places (its count $D1); $03B5 on is a vector (more than ten bytes typed there
  overwrite it).

## cc65's cbm510 runtime

The program in bank 0 from $0003 (a BASIC line that pokes `SEI / LDA #0 / STA $00` into bank 15's $0100 and SYS 256:
the CPU moves to bank 0 at $0105, cc65's start-up); IndReg = ExecReg = 0 between its own accesses; its interrupt
handler in bank 0 (the interruptors first, then TPI 1: the 50 Hz ticker scans the keyboard into its own buffer
`keybuf`/`keyidx` and counts its clock `time`, both in bank 0's zero page); the character set copied to $E000, the
text screen at $F000; the C stack from $FEC3 down; its cross-bank call at $FEC3 and its jump table at $FF6F.

## VICE (xcbm5x0)

- The binary monitor's banks: ram00-ram0f = 0-15 (RAM), 16 = the I/O as the CPU sees it ($D000 the text screen,
  $D800 the VIC-II...).
- No autostart for the CBM-II: DLOAD and RUN typed into the KERNAL's buffer (ten places at a time).
- A snapshot restored has no interrupt from the 6526 any more (checked: before the restore the game's 300 Hz tick
  comes, after it none): the video's planner restores its snapshots in a second VICE (src/c64/video/sesion500.py).
- Drives: an 8050 for a D80 image, a 2031 or 4040 for a D64 (`-drive8type 8050 -drive8truedrive`).
