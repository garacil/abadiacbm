# Group logica_b on the 6502 (Z80 4C46-60F2): notes

Files: `logica_b.s` (the VM, the expression evaluator, the native routines), `logica_b_guiones.s` (generated by
`guiones64.py` from the tape image: the 15 script functions as bytecode and the orientation quirk's tables),
`plat_aleatorio_prueba.s` (the platform call `plat_aleatorio` of the checked build), the group's lines at the end
of `resultados.tsv`.  Build: `./construye.sh`; regenerate the scripts: `python3 -I guiones64.py`.

## The scripts: a VM over the Z80 script code

The 570 RST 08h / RST 10h of the game are all in this group (51E7-60F2).  As `JSR ai_script_test` + inline
bytes they would cost +2 bytes a call plus a CLC before every branch (about 7.4 KB for the group), so I
chose a bytecode interpreter: each script function is `JSR logica_b_vm` followed by bytecode that
is the Z80 code itself (RST 08h `CF expr`, RST 10h `D7 var expr`, JR NZ, JR, JP, JP NZ, CALL, RET, LD A,n,
XOR A) with 6502 operands, plus short forms the generator picks:

| Bytecode | Meaning |
|---|---|
| `E0/E1/E2 v n` | RST 08h `v n =` / `v n >` / `v n <` (v a variable, n a literal) without the evaluator |
| `E4/E5/E6 v n e` | the same followed by JR NZ e |
| `D6 v n` / `D5 v n` | RST 10h of a literal / the same followed by RET |
| `D8 v n w m` | two of those in a row |
| `D0 b` / `D1 b` | CALL hud_say / hud_say_now with its inline phrase byte |
| `D2` / `D3` / `D4` | CALL ai_guillermo_is_close / CALL hud_obsequium_minus_2 / JP ai_stay |
| `C3 k 00`, `CD k 00 b` | tail call / call with an inline byte through `lb_tabla[k]` |
| `CD 0A 00 w.. 0` | util_jump_table_inline 3A5D (its table of bytecode labels follows) |
| JP / JP NZ within reach | JR / JR NZ |

Code that falls into the next script function gets a JR over that function's `JSR logica_b_vm`: the only case
is 5FDD, whose switch falls past its table into 5FEE on day 7 (the integrated build's day-7 states found it: the
VM read the JSR as JR NZ).  Rules: a CF/D7 expression must end at a Z80 opcode (18 20 C2 C3 C9 CD CF D7), as `ai_script_eval` reads it,
so the short forms (D0-D8, E0-E6) are never emitted right after one (the generator falls back to the long form).
Calls with an inline byte go through a 5-byte RAM trampoline (`JSR routine / .byte b / RTS`), so the INLINE
traps of the host work and the callees keep their `JSR x / .byte b` interface.  The VM's instruction pointer is
`zhl` (the Z80's HL after an RST is the expression's end as well); A and the flags of the Z80 are kept in
`lb_va` / `lb_vf` and given to every native call; a native call keeps the bytecode pointer on the 6502 stack, so
script functions call each other (5B21 -> 5FDD, 6016, 6040, 6076) as nested VM runs.

The evaluator `logica_b_eval` has the interface of `ai_script_eval` 3926 (zhl in; zbc = the value, zhl = the
terminator out; A X Y free; the 6502 stack balanced) and is to be replaced by group estado_texto's at the merge
(174 bytes).  The VM needs nothing else from estado_texto (not 391E, 38FC, 3910, 3994, 3A5D).

## Data conventions met on the way

* Object records 2B59h + 5k: +2/+3 is the holder's address when bit 7 of +0 is set (x, y otherwise).  The
  6502 stores the C64 address; punteros64.tsv relocates the field conditionally (flag `held`, added for this
  group).
* Screen positions stay CPC screen addresses in the registers (hud_fill_bar, hud_draw_day_numeral take HL as
  the Z80 does); `lb_scr` converts to the bitmap byte and nibble, `lb_nextline` is vid_next_line, `lb_blit`
  draws a block of nibbles from a C64 graphic or a constant nibble.  The obsequium bar's byte (CPC) becomes a
  nibble by the rule der (`lb_der`), which is what `cola_obsequium` holds; the CPC tail FFh >> (obsequium & 3)
  is computed, so the C64 block `cola_obsequium` (4 bytes) is not needed.
* PANTALLA rules: `der` for the bar, `par` for the day numerals (romanos: rule detalle) and for every routine
  that also draws through a trap; `sim` for the score bar's objects.
* obj_drop_object's orientation (4E4B-4E53) reads the byte at (height << 8) | the low byte of the CPC address
  of the holder's character orientation: garbage of the original (a byte of Z80 code or data).  The 6502 gives
  the same value: the tape image's bytes for Guillermo (88h) and the abbot (B5h), the only holders that drop
  (4DC3, 3C0F), heights 00h-23h (72 bytes of tables), and for heights 1 and 2 the C64 copies of the blocks that
  change there (the initial-state copy, the room links).  Possible cut (about 115 bytes) if I accept a
  different, unused, orientation byte for dropped objects.
* obj_read_manuscript's LD A,R: `plat_aleatorio` (A = a random byte; only bits 0-1 are used).  The checked build
  reads the mirror byte $07BF, which the host still has to fill with the value the Z80's LD A,R reads.

## Checks (final build)

* 8 exploration sessions (4472 frames): 0 differences in each (535578 to 1356252 checked calls a session).
* 16 long scripts largo101-116 (20000 frames): 0 differences in each (3.98 to 6.99 million calls).
* Checked at the top level: the 7 script functions the game calls each frame, obj_pick_up_objects,
  obj_update_key_permissions, obj_drop_on_space, iso_mirror_update, hud_scroll_hour_name, ai_timers_tick,
  ai_clock_init, ai_clock_redraw, hud_draw_guillermo_objects, hud_draw_objects, hud_obsequium_sub.  Checked only
  through those callers: obj_front_position, iso_mirror_character / reflect (up to the room test), the clock
  routines, hud_set_and_draw_day, hud_draw_day_numeral, hud_fill_bar, hud_obsequium_minus_2, the abbot's ceremonies
  5FDD-6076.  Never reached in any session: obj_drop_object (the space bar is never pressed and the abbot never
  drops the parchment), obj_read_manuscript, obj_set_mirror_numeral, the mirror's reflection proper and
  iso_mirror_draw_callback.
* Cycles per call (the 16 long scripts): ai_abbot_think 5583, game_update_camera_and_bonus 4910, ai_severin_think
  3722, ai_berengar_think 3683, obj_pick_up_objects 3358, ai_adso_think 3009, ai_malachi_think 2567,
  iso_mirror_update 584, ai_hour_change_events 441, ai_timers_tick 238: about 28 000 cycles a game frame.
